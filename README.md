# ArbiScan — моніторинг міжбіржового арбітражу (Spot USDT)

Повноцінний прототип: бекенд на Node.js/Express + TypeScript і фронтенд на React + Vite + Tailwind CSS 4. Інтерфейс повністю українською, адаптивний (ПК і мобільні).

Підтримувані біржі: **OKX**, **Bybit**, **Bitget (API V3)**, **Gate**, **MEXC**, **Binance**, **KuCoin**. Котирувальна валюта — лише **USDT**; **USDC повністю виключено** (ні як котирувальна, ні як базова валюта).

## Швидкий старт

Потрібно Node.js **20.19+** (рекомендовано 22, див. `.nvmrc`).

```bash
npm install
npm run dev            # бекенд http://localhost:8787 + фронтенд http://localhost:5173
```

Відкрийте http://localhost:5173. За замовчуванням працює **демо-режим** — згенеровані стакани й мережі з усіма крайніми випадками.

Продакшн-збірка (один процес, бекенд віддає зібраний фронтенд):

```bash
npm run build
npm start              # http://localhost:8787
```

Перевірки:

```bash
npm test               # unit-тести бекенда (стакани, комісії, верифікація, Bitget V3) і фронтенда (фільтри, дедуплікація сповіщень)
npm run typecheck
npm run lint
```

## Налаштування (`server/.env`)

Скопіюйте `server/.env.example` у `server/.env`:

| Змінна | Призначення |
| --- | --- |
| `PORT` | Порт API (за замовчуванням `8787`) |
| `ADMIN_TOKEN` | Токен панелі адміністратора (за замовчуванням `admin` — **змініть**) |
| `OKX_API_KEY`, `OKX_API_SECRET`, `OKX_API_PASSPHRASE` | Read-only ключ OKX — для перевірки мереж/контрактів (`/api/v5/asset/currencies`) |
| `BYBIT_API_KEY`, `BYBIT_API_SECRET` | Read-only ключ Bybit — для перевірки мереж/контрактів (`/v5/asset/coin/query-info`) |
| `GATE_API_KEY`, `GATE_API_SECRET` | Read-only ключ Gate — лише для комісій виводу (`/wallet/withdraw_status`); мережі й контракти Gate публічні |
| `MEXC_API_KEY`, `MEXC_API_SECRET` | Read-only ключ MEXC — мережі/контракти/комісії (`/api/v3/capital/config/getall`) |
| `BINANCE_API_KEY`, `BINANCE_API_SECRET` | Read-only ключ Binance — мережі/контракти/комісії (`/sapi/v1/capital/config/getall`) |

Без ключів LIVE-режим працює (ціни та стакани публічні), але мережі OKX/Bybit/MEXC/Binance позначаються як «Мережа ?», а прибуток — як **попередній**. Bitget (`/api/v3/market/coins`) і KuCoin (`/api/v3/currencies`) віддають мережі з комісіями публічно. Gate віддає мережі й контракти публічно, але комісію виводу — лише з ключем; без нього комісія оцінюється резервним значенням і прибуток лишається попереднім.

Налаштування та демо-сценарій зберігаються у `server/data/*.json` (не в Git).

## Як працює розрахунок

1. **Пари.** З кожної біржі завантажуються лише Spot-ринки `*/USDT` у статусі торгівлі. Активи зіставляються за базовим тикером, а потім **перевіряються**: спільна мережа (нормалізовані назви ERC20/ETH, TRC20/TRX, BEP20/BSC тощо), однаковий контракт (EVM — без урахування регістру), доступність виводу на біржі купівлі та депозиту на біржі продажу, збіг повної назви активу.
2. **Обсяг.** Для кандидатів завантажуються стакани. «Можна купити / продати» — сума в USD за всіма рівнями asks/bids у межах вікна глибини (за замовчуванням ±2% від найкращої ціни), а не лише найкращий bid/ask. Також рахується **макс. прибутковий обсяг** — поки граничний спред після комісій бірж додатний.
3. **Угода на $100** (налаштовується). Симуляція проходить стакан купівлі (VWAP), віднімає тейкер-комісію, комісію виводу в мережі, продає монети по стакану продажу (VWAP) і віднімає комісію продажу. Колонка «$100?» — чи вистачає глибини обох стаканів. Якщо стакан продажу тонкий, прибуток рахується лише на реально виконуваний обсяг.
4. **Статус прибутку.** «Перевірено» — лише якщо обидва стакани завантажено й достатні, мережу/контракт підтверджено і переказ відкритий. Інакше — **«Попередній»** (наприклад, стакан не завантажився — розрахунок за best bid/ask; мережа невідома — використовується резервна комісія мережі з налаштувань).
5. **Підозрілі зв’язки** (різні контракти, різні назви активу, спред вище порогу, ціна-викид відносно інших бірж) за замовчуванням приховані, ніколи не сповіщаються, а їхній прибуток перекреслено. Над таблицею показано, скільки їх приховано.

## Системи безпеки та моніторингу

- **Статус виводів і вводів.** Для кожної спільної мережі сканер перевіряє через API бірж `withdrawEnabled` на біржі купівлі та `depositEnabled` на біржі продажу (`transfer.legs`). Якщо всі спільні мережі закриті — зв’язка отримує статус **«Недоступна для переказу»** (`transfer.status = blocked`), її прибуток перекреслено, вона не потрапляє у «Лише доступні», у сповіщення, а в журналі отримує вердикт «Заблокована». Статуси гаманців у LIVE оновлюються кожні `assetInfoRefreshSec` (120 с за замовчуванням); час останньої перевірки видно в деталях.
- **VWAP і прослизання.** Ціни купівлі/продажу — VWAP за глибиною стакана під обсяг угоди. У деталях і таблиці показано спред за найкращими bid/ask **і** спред за VWAP (`slippage.vwapSpreadPct`), прослизання кожної ноги та частку спреду, яку воно з’їдає. Якщо частка перевищує поріг (`maxSlippageShareOfSpreadPct`, 50%) — попередження.
- **Комісії мереж.** Комісія виводу береться з біржі в реальному часі для обраної (найдешевшої відкритої) мережі й віднімається з прибутку. Розклад витрат `costs` показує: валовий спред → прослизання → комісії бірж → комісія мережі → чистий прибуток. Якщо комісія мережі ≥ валового спреду або угода стає збитковою — попередження (`network_fee_exceeds_spread` / `unprofitable`). Перевіряється й мінімальна сума виводу (`below_min_withdraw`).
- **Журнал зв’язок.** Кожна поява спреду від `journal.minSpreadPct` (2%) записується в `server/data/journal.json`: час появи/зникнення, біржі, спред у момент появи/максимальний, спред за VWAP, прибуток, стан стакана і ліквідності, статус переказу, волатильність, попередження та **вердикт** (робоча / заблокована / збиткова / підозріла / не перевірена). Вкладка «Журнал» у шапці: статистика, частка хибних сигналів, фільтри за вердиктом/тикером/періодом, експорт CSV.
- **Ризик однієї ноги.** Сканер зберігає mid-ціни кожного ринку і рахує розмах за вікно (`volatility.windowSec`, 60 с). Розмах ≥ `warnPct` — «Рухлива ціна», ≥ `highPct` — «Волатильно» з попередженням, що спред може зникнути, поки монети йдуть між біржами.

Поле `actionable` у відповіді API — підсумок: не підозріла, не заблокована, прибуток після всіх витрат > 0.

## Фільтри

- Галочка **«Лише доступні»** над таблицею залишає тільки зв’язки, які реально можна виконати: переказ відкритий у спільній мережі (вивід на біржі купівлі й депозит на біржі продажу), обидва стакани покривають угоду, немає ознак підозри. Поруч — кількість таких зв’язок.
- Фільтр мережі за замовчуванням вимкнений («усі мережі»). Коли його ввімкнено, зв’язки з невідомою мережею **за замовчуванням не приховуються** (окремий перемикач).
- Якщо список порожній, показується, **який саме фільтр скільки зв’язок приховав**, з кнопкою «Скинути» для кожного, або причина з боку даних (сканер не готовий, помилка API біржі, менше двох бірж, немає кандидатів).
- На мобільних фільтри відкриваються висувною панеллю.
- Стан фільтрів зберігається в `localStorage`.

## Сповіщення

Кнопка «Сповіщення» в шапці вмикає браузерні сповіщення (Notification API) і вбудовані сповіщення в інтерфейсі.

- Спрацьовують, коли **з’являється нова** зв’язка зі спредом від 2% (поріг налаштовується в адмін-панелі).
- Дедуплікація: зв’язка, що залишається в списку, не сповіщається повторно; після зникнення — не раніше ніж через паузу (30 хв за замовчуванням). Стан зберігається між перезавантаженнями.
- Не сповіщаються: підозрілі зв’язки та зв’язки з закритим виводом/депозитом («Недоступна для переказу») або менші за мін. суму виводу.
- Текст: біржі купівлі/продажу, спред і спред за VWAP, статус стакана й ліквідності, прибуток з комісією мережі (з позначкою «попередній», якщо не перевірено), попередження.
- Сповіщення працюють на повному списку зв’язок і **не змінюють фільтри**. Клік відкриває зв’язку; якщо вона прихована фільтрами — з’являється підказка.

## Панель адміністратора

Кнопка «Адмін» → вхід за `ADMIN_TOKEN`:

- **Загальні:** демо/LIVE, обсяг тестової угоди, вікно глибини, кількість рівнів стакана, пороги спреду, ліміт кандидатів, мін. обіг, інтервал сканування, період оновлення статусів гаманців.
- **Біржі та комісії:** увімкнення бірж, тейкер-комісії, резервна комісія мережі.
- **Ризики та журнал:** поріг прослизання, вікно і пороги волатильності, увімкнення/поріг/розмір журналу, очищення журналу.
- **Сповіщення:** поріг спреду, пауза між повторами.
- **Демо-дані:** редагування JSON-сценарію (ціни, зміщення, глибина, мережі, контракти, спецвипадки), перемішування цін, скидання.
- **Імпорт / експорт:** JSON-файл з налаштуваннями та демо-сценарієм (валідується на сервері), скидання налаштувань.

## Обмеження

- Це інструмент моніторингу й симуляції: ордери не виставляються. Прибуток ніколи не гарантований — ціни змінюються під час переказу.
- Комісії бірж задаються вручну (базові тейкер-ставки), без урахування VIP-рівнів.
- Час переказу та мінімальні суми виводу не враховуються в прибутку.
